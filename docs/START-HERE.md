# 从这里开始：零基础复现 MCU Debug Tool

## 1. 这套教程写给谁

默认学习者满足下面的情况：

- 没使用过 Git 也可以完成前五章；
- 没安装过 Visual Studio C++ 编译环境；
- 没安装过 Qt 和 Qt Creator；
- 不知道 CMake、Kit、Debug、Release 是什么；
- 只学过少量 C/C++，没有做过 Qt Widgets 程序；
- 不知道串口、插件、信号槽、线程和协议解析如何组合成上位机。

教程不能要求学习者“自己参考完整工程补齐”“照着类似代码写”“自行选择合适组件”。出现选择时，课件必须明确告诉他点哪一项；出现代码时，必须给出完整文件内容或精确修改位置。

## 2. 最终能复现什么

完成全部课程后，学习者应能从一个空白 Qt Widgets 窗口，逐步做出完整 MCU/设备调试上位机：

- 串口、WinUSB、libusb 和 CandleLight CAN FD 设备接入；
- 原始数据、串口数值和 CAN 帧协议解析；
- 原始数据显示、曲线、仪表盘；
- HEX 命令、周期发送和滑块控制；
- 插件扫描、通道分发、有界缓冲和线程隔离；
- 会话保存、重连、错误提示和发布；
- CAN FD 链路测试与受控的 AGV 测试入口。

“复现成功”不只是界面长得像，还要求构建通过、插件能加载、数据流能验证、错误路径可观察、退出时不残留设备和线程。

## 4. 学习时怎么使用仓库

教师维护仓库有三条主要分支，学生第一步不需要操作它们：

- `dev`：完整成品，只由课程维护者核对真实行为；
- `teaching/environment-setup`：第一步固定课件来源，学生阅读文档但不克隆源码；
- `teaching/from-zero`：课程制作分支，标准答案按顺序增长。

零基础学习者不需要进入 `dev` 查代码，也不需要自己比较分支。环境课先从国内下载源逐个安装工具，再由学生在 Qt Creator 中新建自己的本地工程；不拉取任何现成项目。

推荐的学习方式：

1. 严格从环境安装课开始，通过浏览器阅读，不执行 `git clone`；
2. 一次只学一课，不提前复制后面的代码；
3. 每输入一小段就保存并构建；
4. 结果与课件一致后才提交；
5. 不一致时停在当前步骤，先根据“常见错误”排查；
6. 每课完成后再进入下一课。

## 5. 先认识六个词

### 源码

人编写的 `.cpp`、`.h`、`.ui`、`CMakeLists.txt` 等文件。

### Qt

C++ 图形界面和应用开发库。本项目主要使用 Qt Core、Qt Widgets 和 Qt Serial Port。

### Qt Creator

用于打开工程、编辑代码、设计界面、构建、运行和调试的 IDE。Qt Creator 本身不是 Qt 库，也不是 C++ 编译器。

### MSVC

Microsoft 的 C++ 编译器，把 C++ 源码转换为 Windows 可执行程序和动态库。

### CMake

读取 `CMakeLists.txt`，告诉编译工具本项目有哪些文件、目标和依赖。

### Kit

Qt Creator 中的一套构建组合，包括 Qt 版本、C++ 编译器、CMake、调试器和运行设备。本教程始终使用 Qt 6.11.2 + MSVC 2022 + x64。

## 6. 每一课必须长什么样

后续实操课统一使用下面的结构：

### A. 本课结果

先展示完成后能看到或能测到什么，避免学习者不知道目的。

### B. 开始条件

写清起始源码备份、需要的软件、设备，以及上一课应通过的检查。

### C. 本课只学哪些新概念

每课控制在 1–3 个核心概念。其他内容暂时使用简单实现，不提前引入未来架构。

### D. Qt Creator 点击步骤

菜单路径同时给出中文和英文，例如：

```text
文件/File > 新建文件/New File > C++ > C++ Class
```

对话框中的类名、基类、保存目录和勾选项都必须写明。

### E. 完整代码

新文件提供完整内容；修改旧文件时给出“找到哪一段、替换成什么”。代码块后解释每个新类和关键语句的职责，不假定学习者已经理解 Qt 隐式行为。

### F. 构建和运行

明确点击锤子还是绿色三角、查看哪个输出窗口、正常结果是什么。

### G. 自测

给出可以重复执行的输入、动作和预期输出。涉及硬件时先提供无硬件测试，再提供有硬件测试。

### H. 常见错误

错误必须包含：看到的现象、最可能原因、检查位置和修复动作。

### I. 阶段备份

提供本课确切的源码备份目录名和需要保留的文件，不要求学生先学习 Git。

### J. 本课小结

说明新增了什么、哪些地方仍是简化实现、下一课将替换什么。

## 7. 教学代码的控制原则

- 一课只打通一个小而完整的路径；
- 新功能默认不超过约 250 行有效生产代码和两个新文件；超过时拆课；
- 不为了以后可能使用而提前添加接口、工厂或注册表；
- 硬件、协议和 UI 必须分开，但不制造只有一行转发的空层；
- 协议字段、端序、CRC、超时和重试必须有现有代码、固件或测试记录作为依据；
- 安全停止、边界、容量、超时和资源释放不能为了“教学简单”而省略；
- 中文注释解释原因、时序、硬件限制和容易踩坑的边界，不复述语法。

## 8. 如何判断自己没有跟丢

每课结束时应同时满足：

- Qt Creator 左侧项目树中的文件与课件一致；
- `Ctrl+B` 无编译错误；
- 本课运行结果或测试结果一致；
- 本阶段源码备份已经创建；
- 备份中不包含构建产物；
- 能用自己的话解释数据从哪里来、经过什么类、最终到哪里。

如果某一步不一致，不要继续输入后面代码。记录 Qt Creator 的完整错误文本、当前课号和操作步骤，再进行排查。
